# 前置问询与输入分流

## 一、六种输入形态

| 形态 | 判定依据 | 处理路径 |
|---|---|---|
| ① 完整剧本（整剧 / 整片） | 有分场、有完整台词 | 直接进关卡 1；按时长分段落做提案，不要一次把全剧拆完 |
| ② 单集 / 单段剧本 | 一场到数场，台词完整 | 最优输入，直接提案 |
| ③ 剧情大纲（无台词） | 只有情节脉络 | **先问一句**：是要「按大纲补台词再分镜」还是「直接分镜、台词现场写」。前者要先产出台词稿给用户确认；后者在分镜表的台词列标注「（拟）」并告知用户需替换 |
| ④ 不完整输入（大纲 + 前几集） | 后面没写 | 只对已有部分提案；缺口列出「待补场次清单」交给用户 |
| ⑤ 已有分镜表 | 用户手上已经有半成品 | 问清目的：重做五案 / 按某原型改造现有分镜 / 只转提示词。三种路径完全不同，不要默认第一种 |
| ⑥ 单场片段 / 一句话想法 | 极短 | 先确认时长与用途（是独立短片还是全片中的一段），再提案 |

## 二、参数缺省表

用户没答就按下面走，并在产出开头写明「本次采用：XX（缺省值），如需调整告诉我」。**不要为了问参数中断产出**，除了影响方向的三项：

必须问清的三项（影响五案是否会做白工）：
1. **目标时长** —— 镜数全靠它算。
2. **画幅比例** —— 竖屏和横屏的构图方案完全不同。
3. **有没有可参考的视觉参考**（片单 / 参考图 / 已生成角色图）—— 有的话五案才有锚。

可缺省的三项：目标模型（默认 Seedance 2.5）、剧本完整度（自动判定）、是否有偏好方向（默认走比稿）。

## 三、问询话术

把问题**合并成一次提问**，不要用连续追问折磨用户。示例：

> 开工前确认三件事：
> 1. 目标成片时长？画幅是 16:9 还是 9:16？
> 2. 目标模型用哪个（默认 Seedance 2.5）？
> 3. 有没有视觉参考（片单 / 参考图 / 已生成的角色图）？有的话发我，没有我就按五个不同方向各出一案给你挑。

## 四、时长与镜数的换算基准

```
镜数下限 = 目标秒数 ÷ 4     （抒情 / 长镜基调）
镜数上限 = 目标秒数 ÷ 3     （冲击 / 碎切基调）
参考中段 = 目标秒数 ÷ 3.5
```

90 秒 → 23–30 镜；120 秒 → 30–40 镜；30 秒 → 8–10 镜。

某案定义为长镜流时，允许镜数低于下限，但**必须在提案卡的预估成本里写明「实际生成条数会因切分高于镜数」**。

## 五、用户明确拒绝比稿时怎么办

少数用户会说「别给方案了，直接来」。此时：
- 仍然做五轴取值判断，但只输出**一句话的方案依据**（如「按 P2 手持纪实方向走」）放在产出开头；
- 后续流程照旧，交付物仍含完整分镜表与提示词；
- 在产出末尾附一句「若方向不对，可回到五案比稿」。
